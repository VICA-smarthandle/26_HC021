## 1. 왜

지도를 그린 뒤 고정 장애물(책상·도커)이 생기거나 옮겨지면 그 구간에서 AMCL 이 위치를 못 잡는다.
지금은 지도를 통째로 다시 그리거나 pgm 을 손으로 고쳐야 한다(10-12 홈 앞 점, 10-30 회색 점).

- 11-07 킨텍스 `map_1103_142858` 홈: 뒤 벽 앞에 구조물이 생겨(지도 1.5 m → 라이다 ≈1.0 m) 뒤쪽 스캔 점
  94 % 가 지도와 0.2 m 넘게 빗나갔고, 로봇이 홈 0.6 m 옆에서 돌다 섰다.
- 지도는 파일 한 벌(`vica_ros2_ws/maps/<id>.{pgm,yaml,png}`)이고 Nav2 는 `map_server` 의 `load_map` 으로
  재시작 없이 새 지도를 받는다(Humble `map_server.cpp` `loadMapCallback` 이 `/map` 을 다시 발행, AMCL 은
  `first_map_only` 기본 false 라 `map_` 만 교체·입자 유지, `static_layer` 는 다음 `updateBounds` 에서 재구성).
  금지구역이 이미 같은 길(`/keepout_filter_mask_server/load_map`)을 쓴다.

## 2. 확정 결정(사용자, 11-18)

1. 부분 갱신은 로봇이 **정지한 채** 라이다 스캔으로 덮어쓴다. SLAM 이어 그리기는 하지 않는다.
2. 지우기는 **별도 기능**이다. 실제로 없어진 것만 지운다. 스캔에 다른 것이 찍히면 지우기로 지운다.
3. 스캔 범위는 라이다 중심 반경 **1·2·3 m 중 고르기, 처음 값 2 m**.
4. 지우기는 **사각형, 여러 개를 그려 한 번에**. 붓은 넣지 않는다.
5. 위치 오차가 지도에 최소한으로 남게 한다.
6. 이름: 칸 `지도 수정` · 버튼 `지우기`·`부분 스캔` · 화면 `지도 부분 지우기`·`지도 다시 스캔하기`.
   문구 전체는 83번 보드. 코드 안 식별자는 `map_fix`·`erase`·`scan` 을 쓴다.

## 3. 목표 · 하지 않는 것 · 실패로 보는 것

목표
- G1 지우기: 사각형 여러 개 안의 검은 칸(0)·회색 칸(205)을 빈칸(254)으로 한 번에 바꾼다.
- G2 부분 스캔: 반경 R 안에서 **변경된 칸만** 고친다(새로 생긴 칸 → 0, 없어진 칸 → 254).
- G3 Nav2·미션·음성을 재시작하지 않는다. 지도 크기·origin·resolution 은 바꾸지 않는다 → 목적지
  (`~/vica_data/destinations/<id>/`)·레일(`_route.geojson`)·금지구역(`_keepout.*`) 좌표가 그대로 맞는다.
- G4 수정마다 백업하고 가장 최근 것부터 되돌린다.
- G5 부분 스캔은 수정 전·후 `위치 맞춤`(%)을 같은 스캔으로 재서 보인다.

하지 않는 것
- SLAM(Cartographer·slam_toolbox) 이어 그리기 — 저장된 pbstream·posegraph 가 없다.
- 주행 중 자동·상시 갱신, 주행 중 수정.
- 붓 지우기, 손으로 벽 그려 넣기.
- 도킹 좌표·홈·목적지·레일·금지구역 자동 수정(도킹은 도킹 세션 소관).
- 수정 뒤 AMCL 자세 재설정(`/initialpose`). 맞춘 자세는 그리는 데만 쓴다.
- 미션 장애물 안내의 지도 다시 읽기(11절 5번, 11-19 확정). 미션은 기동 때 pgm 을 한 번 읽어
  `ObstacleJudge` 에 넣으므로(`mission_manager_node._setup_obstacle_narration`), 수정한 뒤에도 미션을 다시
  띄우기 전까지 장애물 안내는 옛 지도로 "지도에 없는 물체"를 판정한다. 수정 전과 같은 동작이다.
  대신 수정할 때 미션이 켜져 있으면 앱에 알림 한 줄을 띄운다(6.3 끝 알림).
- `maps/.original/<id>.pgm`(저장 때 정렬 전 원본) 갱신.

실패로 보는 것(동작해도 실패)
- 틀린 자세로 그려 기존 벽 옆에 이중 벽·단차가 생긴다.
- 안 바뀐 벽이 반 칸씩 옮겨지거나 깎인다.
- 백업 없이 원본을 잃는다. 파일과 Nav2 의 지도가 서로 달라진 채 남는다.
- 주행 중·목적지를 쥔 채 지도가 바뀐다.

## 5. 접근

### 5.1 기능 방식 — 결정됨

| 방식 | 내용 | 판정 |
|---|---|---|
| A 손으로 칠하기·지우기 | 앱에서 칸을 직접 수정 | **지우기만 채택.** 새 물체를 cm 단위로 그릴 수는 없다 |

## 6. 설계

### 6.1 구성

```text
앱(Flutter)
  └─ rosbridge ─ /vica/map_fix (서비스, 새)      요청·응답
              └─ /vica/map_fix/state (토픽, 새)   스캔 진행·결과
map_fix_node (새)
  ├─ map_fix.py (새, 순수)   칸 계산·백업·되돌리기·변경 판정
  ├─ vica_nav2.pose_score     자세 다시 맞춤·위치 맞춤 %
  ├─ 구독 /scan /odom /robot_status /tf
  └─ 호출 map_server load_map
```

### 6.2 공용 계약(새) — 승인(11-18)

서비스 `vica_interfaces/srv/MapFix.srv` 하나, 토픽 하나. 타입을 여러 개 만들지 않는 이유는
`SaveKeepout.srv` 와 같다(값은 앱과 이 노드 둘만 읽는다).

```text
string map_id
string action      # 아래 표
string args_json
---
bool accepted
string reason      # '' 이면 통과. 6.7 표
string message
string result_json
```

| action | args_json | result_json |
|---|---|---|
| `get` | – | `{lock, can_scan, history:[{at, kind, radius_m, added, removed, black, gray, rects}]}` |
| `erase_count` | `{rects:[{x_min,y_min,x_max,y_max}]}` | `{rects:[{w_m,h_m,black,gray}], black, gray}` (파일 안 바꿈) |
| `erase` | 위와 같음 | `{black, gray, applied}` |
| `scan_check` | – | `{score, used_beams, kept_beams, ambiguous, x, y, yaw, hits:[[x,y]…]}` (자세 다시 맞춤만. `hits` 는 맞춘 자세에서 본 라이다 점, 최대 180개 — 78번 화면의 파란 점) |
| `scan_start` | `{radius_m}` | `{session}` — 진행은 토픽 |
| `scan_cancel` | `{session}` | – |
| `scan_apply` | `{session}` | `{added, removed, score_before, score_after, applied}` |
| `scan_discard` | `{session}` | – |
| `undo` | – | `{kind, applied}` |

토픽 `/vica/map_fix/state`(`std_msgs/String` JSON, 2 Hz, 세션이 있을 때만):
`{session, phase: refine|step_back|scanning|preview|failed, remaining_s, radius_m, moved_m, moved_deg,
score_before, score_after, added, removed, cells:[[x,y,kind]…], reason}`.
`cells` 는 지도 좌표(m) 칸 중심과 종류(1 새로 생김, −1 없어짐), 최대 2,000개.

좌표는 전부 ROS map 좌표(m)다. `map_id` 는 `^[A-Za-z0-9_-]+$` 만 받는다.

### 6.3 잠금·반영 규칙

| 상태 | 지우기 | 부분 스캔 | 반영 |
|---|---|---|---|
| 주행 지도 · 쉬는 중 · Nav2 켜짐 | 됨 | 됨 | 파일 → `load_map` |
| 주행 지도 · 쉬는 중 · Nav2 꺼짐(앱에서 주행을 끈 상태) | 됨 | 안 됨(`no_pose`) | 파일만(`no_nav2`). Nav2 가 켜질 때 읽는다 |
| 주행 지도가 아닌 지도 | 됨 | 안 됨(`not_current_map`) | 파일만. 다음에 그 지도로 주행할 때 읽힌다 |
| 쉬는 중이 아님 | 안 됨(`busy_driving`) | 안 됨 | – |
| rosbridge 끊김 | 앱이 잠금(`오프라인`) | | |

- '쉬는 중'(전부 만족): `/robot_status` 의 `current_goal` 이 비었고 · `status` 가 `moving` 이 아니고 ·
  `dialog_state` 가 `''`·`idle`·`none`·`arrived`·`failed`·`estopped` 중 하나이고 · '정지'다.
  `dialog_state` 목록은 앱 수동 주행의 허용 목록(`_manualIdleStates`)과 같다. 순찰(일시정지 포함)·대기·
  사람 접근·처음 안내·묻는 중은 잠긴다.
- '정지' = `/odom` 선속도 < 0.02 m/s 이고 각속도 < 0.05 rad/s(`vica_amcl_probe.py` 의 문턱과 같다).
- 잠겨 있으면 거절한다. 미뤄 두었다가 나중에 대신 수정하는 일은 없다.
- `load_map` 결과별 처리
  - 서비스가 없다(Nav2 꺼짐): 파일만 쓰고 성공으로 답한다. `applied=false`, `no_nav2`, 문구는 금지구역과
    같은 `Nav2가 실행되면 적용됩니다.`
  - 실패 응답: 방금 쓴 파일을 백업에서 되돌리고 `apply_failed`.
  - 10 s 안에 응답 없음: 이미 반영됐을 수 있어 파일은 둔다. `applied=false`, `apply_timeout`. 노드가
    쉬는 중일 때 5 s 마다 같은 파일로 `load_map` 을 다시 걸고, 성공하면 그만둔다.
- 끝 알림: `applied=true` 면 `지도를 수정했습니다.`, 아니면 로봇이 보낸 `message` 를 그대로 띄운다.
- 미션 알림(11-19 사용자): `erase`·`scan_apply`·`undo` 가 성공했을 때 미션이 켜져 있으면 응답
  `result_json` 에 `mission_stale: true` 를 싣고, 앱은 끝 알림에 한 줄을 덧붙인다 —
  `Mission Manager에는 적용되지 않았습니다.` / `주행을 껐다 켜면 적용됩니다.`(두 줄, 99번 보드, 11-19 확정 —
  '반영'을 앱의 다른 말과 같은 '적용'으로 통일).
  '미션이 켜져 있다' = `/robot_status.dialog_state` 가 빈 값이 아니다(미션이 1 Hz 로 상태를 내는 중).
  미션이 꺼져 있으면 다음에 켜질 때 새 지도를 읽으므로 알림이 없다. 주행 묶음(`vica-drive.target`:
  nav2·posecheck·mission·handle·monitor)을 껐다 켜면 미션이 다시 뜬다.

### 6.4 지우기

1. 사각형마다 칸 중심이 사각형 안에 드는 칸을 고른다. 지도 밖은 잘라낸다.
2. `erase_count`: 고른 칸 중 0(검은 칸)·205(회색 칸) 수를 세어 돌려준다. 앱은 사각형이 바뀔 때마다 부른다.
3. `erase`: 백업 → 고른 칸을 254 로 → pgm·png 쓰기 → 6.3 규칙대로 반영 → 기록 한 줄.
4. 구역(사각형)은 한 번에 10곳까지(11-19 사용자, 처음 20). 한 변이 0.05 m 보다 작으면 `too_small`, 전부 지도 밖이면
   `out_of_map`. 문구의 말은 앱 화면과 같은 '구역'·'곳'이다(`한 번에 10곳까지 지울 수 있습니다.`).
5. 여러 사각형을 한 번에 지워도 백업·기록·되돌리기는 한 묶음이다.

### 6.5 부분 스캔

순서: 자세 다시 맞춤 → 물러나기 5 s → 스캔 모으기 5 s → 변경 판정 → 미리보기 → 적용 또는 버리기.

**(1) 자세 다시 맞춤** — AMCL 자세는 출발값으로만 쓴다.
- 1회째(거친 맞춤): 스캔 1개를 `pose_score` 3단계 탐색으로 지도에 맞춘다(출발값 = TF map→base, 방향
  힌트 = AMCL yaw). `pose_score` 는 고치지 않는다.
- 남길 빔: 1회째 자세에서 끝점이 지도의 **벽 겉 칸** 0.10 m 안에 떨어지는 빔(안 바뀐 벽). 변경된 물체의
  빔이 자세를 끌지 못하게 뺀다. 겉 칸 = 이웃 8칸 가운데 빈 칸이 있는 검은 칸. 검은 칸 전체를 기준으로
  하면 두꺼운 벽 속은 어디나 거리 0 이라 끝점이 벽 속으로 파고드는 자세도 좋게 보인다(11-19 구현 중 바꿈).
- 2회째(정밀 맞춤): 남긴 빔 끝점에서 가장 가까운 벽 겉 칸까지 거리(거리표를 칸 사이 선형 보간 —
  `scripts/drive_diag` ①과 같은 방식)의 제곱 평균이 가장 작은 자세를 1회째 주변 ±0.05 m·±1° 에서 찾는다.
- 통과 조건(전부): 남긴 빔 ≥ 60개 · 남긴 빔 ÷ 유효 빔 ≥ 50 % · 남긴 빔 거리 RMS ≤ 0.05 m(11-19 실기로 0.03 → 0.05, 아래 값 줄 참고) · 2회째가
  탐색 범위 끝에 걸리지 않는다 · 출발 자세(AMCL)에서 옮긴 양 ≤ 0.30 m·10°. 하나라도 어기면 `low_match`.
  마지막 조건은 장면이 크게 바뀌어 엉뚱한 벽에 붙는 것을 막는다(11-19 시험: 세 면이 칸막이로 가려진 장면
  에서 0.7 m 떨어진 자세에 붙었다) — 그만큼 틀렸으면 초기 위치부터 다시 잡는다.
- 구분 검사: 2회째 자세를 로봇 기준 앞뒤 ±0.10 m, 좌우 ±0.10 m, 방향 ±2° 로 밀어 본다. 밀었을 때 남긴
  빔의 거리 RMS 가 앞뒤·좌우는 0.02 m, 방향은 0.01 m 보다 적게 늘어나면(양쪽 가운데 덜 늘어난 쪽 기준)
  그 축은 구분되지 않는다 → `ambiguous`(앞뒤·좌우·방향). 긴 복도에서 앞뒤 위치가 정해지지 않는 경우다.
  처음 설계는 '민 뒤에도 벽 0.05 m 안에 남는 빔이 80 % 를 넘으면'이었는데, 벽이 가까운 작은 방에서 2° 를
  돌려도 끝점이 벽을 따라 미끄러질 뿐이라 방향이 구분되지 않는다고 잘못 나와 바꿨다(11-19 구현 중).
- 화면의 `위치 맞춤 %` 는 초기 위치 잡기와 같은 잣대다: `pose_score` 점수(유효 빔 전부, 최대 180개·11 m,
  `sigma_hit` 0.2). `scan_check.score`·`score_before`·`score_after` 모두 이 값이고 반경 R 과 무관하다.
  이 점수는 통과·구분 판정에는 쓰지 않는다 — 5 cm 를 밀어도 99.5 → 97.3 밖에 안 떨어져(`pose_score.py`
  2026-09-02 실측) 정밀 판정에는 무디다.
- `scan_check` 는 이 단계만 돌려 78번 화면의 `위치 맞춤 84 %` 와 라이다 점을 낸다.

**(2) 물러나기 5 s** — 누른 사람이 원 안에 서 있으면 지도에 찍힌다. 노드가 센다(토픽 `remaining_s`).

**(3) 스캔 모으기 5 s** — 모든 스캔을 (1)의 자세로 지도에 얹는다.
- 빔 끝점이 [0.25 m, R] 안이면 그 칸에 '맞음', 라이다에서 끝점 직전까지 지나간 칸(R 안)에 '지나감'.
  R 보다 먼 빔은 R 까지만 '지나감'. 값이 없는 빔(inf·nan)은 버린다.
- 칸마다 '맞은 스캔 수'·'지나간 스캔 수'를 센다(스캔 하나에서 여러 빔이 맞아도 1).
- 모으는 동안 '정지'가 깨지면 `moved` 로 끝낸다.

**(4) 변경 판정** — 반경 R 안의 칸만 본다. N = 모은 스캔 수.
- 새로 생김: 지금 검은 칸이 아니고, 맞은 스캔 ≥ 0.8 N, 주변 1칸(8방향) 안에 검은 칸이 없다.
- 없어짐: 지금 검은 칸이고, 지나간 스캔 ≥ 0.8 N, 맞은 스캔 ≤ 0.1 N, 주변 1칸 안에 '새로 생김' 후보가
  없고, 그 칸을 지나간 빔이 0.10 m 넘게 더 나아갔다(벽을 스치는 빔이 벽을 깎지 않게).
- 나머지는 그대로 둔다. 회색 칸(205)은 새로 생긴 칸이 될 때만 바뀐다.
- 변경된 칸이 0 이면 `no_change`.

**(5) 미리보기** — 토픽 `phase: preview` 로 칸 목록·개수와 `score_before`(지금 지도)·`score_after`(고친
지도)를 보낸다. 둘 다 같은 스캔·같은 자세·같은 `pose_score` 잣대다. 5분 안에 답이 없으면 버린다.

**(6) 적용** — 백업 → 새로 생김 0, 없어짐 254 → pgm·png 쓰기 → `load_map` → 기록 한 줄.

값(시작값, 0단계 실측으로 고친다): 물러나기 5 s · 모으기 5 s · 0.8 N · 0.1 N · 주변 1칸 · 0.10 m ·
남긴 빔 60개·50 % · RMS 0.05 m(11-19 실기: 위치가 맞는데도 3.4~3.7 cm — 지도 한 칸 5 cm 안 벽 자리 차이, 시작값 0.03 에서 고침) · 옮긴 양 0.30 m/10° · 구분 검사 ±0.10 m → 0.02 m, ±2° → 0.01 m.

오차가 남는 양(가정): 방향이 0.5° 틀리면 원 끝에서 1 m 0.9 cm · 2 m 1.7 cm · 3 m 2.6 cm, 지도 한 칸
5 cm. 0.5° 는 0단계에서 재서 확인한다 `[미검증]`.

### 6.6 백업 · 되돌리기 · 기록

- 자리: `maps/.fix_backup/<map_id>/<YYYYMMDD_HHMMSS>_<erase|scan>/` 에 고치기 전 `pgm`·`png` 와

## 7. 시험

0단계 — 일회용 실측(저장소 밖 `~/vica_data/map_fix_tests/<날짜>/`, 기록은 지우지 않는다)
- 장면(11-19 사용자): **도킹 스테이션 구조물을 지도에 추가**한다(주행 지도 `vica_map_0630`). 비교용으로
  벽만 있는 자리 1곳도 잰다. 6.5 를 파이썬 스크립트로 돌린다.
- 도킹 실기와 겹치지 않게 두 단으로 나눈다. ① 읽기만: 로봇이 도크 근처에 서 있을 때 `/scan`·TF·
  `/amcl_pose` 를 몇 초 기록해 **지도 사본**에서 계산한다(운영 `maps/`·Nav2 는 안 건드림). ② 실제 지도
  반영(`load_map`)은 도킹 시험이 멈춘 때 사용자 확인을 받고 한다 — 지도에 도크가 생기면 costmap 과 도킹
  접근에 영향이 갈 수 있다.
- 본다: ① 같은 자리 20회 자세 다시 맞춤의 흩어짐(목표 x·y 표준편차 ≤ 1 cm, 방향 ≤ 0.3°)
  ② 아무것도 안 바뀐 장면에서 변경된 칸 0 ③ 상자를 옮긴 장면에서 새 칸이 줄자 위치 ±1칸
  ④ 수정 전·후 위치 맞춤 ⑤ 방·모서리에서는 구분 검사가 통과하고 긴 복도 한가운데에서는 `ambiguous`
  가 나오는지(남는 빔 비율 실측). 결과로 6.5 의 값을 고친다.
- 주행 묶음이 켜져 있을 때는 무거운 분석을 돌리지 않는다.

단위 시험(로봇 없이 pytest, `VICA_Supervisor/ros2/test_map_fix.py`)
- 지우기: 칸 고르기 경계·지도 밖 잘라내기·0/205 세기·여러 사각형 겹침.
- 백업·되돌리기: 왕복 뒤 바이트 동일, 10개 넘으면 오래된 것 삭제, 쓰기 도중 실패 시 원본 유지.
- 변경 판정: 합성 지도·합성 스캔으로 새로 생김·없어짐·스치는 빔·반 칸 어긋난 벽·지나가는 사람(0.8 N 미만).
- 자세 다시 맞춤: 변경된 물체가 섞인 합성 스캔에서 2회 맞춤이 1회보다 참값에 가깝다. 복도 합성 장면은

`map_list_node` 시험 보강.

## 8. 위험 · 모르는 것

- 자세 다시 맞춤이 틀리면 오차가 지도에 남는다. 통과 조건·구분 검사·미리보기·되돌리기로 막지만 0이 되지는
  않는다. 0단계의 ①이 목표를 못 넘으면 반경 상한을 2 m 로 낮추는 것을 다시 묻는다.
- 유리·검은 물체는 빔이 지나가 '없어짐'으로 보일 수 있다 → 미리보기에서 사람이 본다.
- 기존 지도가 틀어진 구간에서는 그 틀어짐에 맞춰 그려진다(주변과는 일관).
- `load_map` 뒤 AMCL 변동 `[미검증]`. 크면 적용 뒤 `/request_nomotion_update` 를 부를지 다시 정한다.
- 잘못 지운 실제 벽은 라이다 `obstacle_layer` 가 가까이에서만 막는다. 벽 밖 회색도 Nav2 에서는 빈칸이라
  경계 벽을 지우면 경로가 벽 밖으로 날 수 있다 → 77 팝업 문구로만 알린다.
- 새 물체가 레일 위에 놓여도 레일은 그대로다 — 사람이 레일을 고쳐야 한다.

## 12. 검토에서 내가 정한 것(사용자 결정 아님)
