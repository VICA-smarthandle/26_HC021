## 3. 수동 주행

### 3.1 동작

- 원격 주행 화면 맨 위 '목적지 주행 / 수동 주행'에서 고른다. 수동 주행이면 목적지 카드 대신 조종판이 나온다.
- 조종판은 3×3 버튼: 앞 왼쪽 선회·앞으로·앞 오른쪽 선회 / 제자리 왼쪽 회전·정지·제자리 오른쪽 회전 / 뒤 왼쪽 선회·뒤로·뒤 오른쪽 선회.
- **누르고 있는 동안만** 50 ms(20 Hz)마다 `/cmd_vel_req` 를 보낸다. 손을 떼면 0 을 한 번 보내고 멈춘다.
- 속도 칸 하나(0.1~0.7 m/s, 0.1 단위). 회전 속도는 `max(0.2, 속도)` rad/s 로 같이 오르내린다.
- 웹 키보드: 화살표(↑+← 처럼 같이 누르면 선회), teleop 자판 `u i o / j k l / m , .`, `k`·Space 정지, `q`·`z` 속도 ±0.1.
  화면에는 "웹에서는 키보드로도 조종할 수 있습니다." 한 줄만 둔다.
- 출발은 가속 3.0(m/s², rad/s²): 50 ms 마다 0.15씩 올라 0.3 m/s 까지 0.1 s, 0.7 m/s 까지 약 0.23 s. 줄이기·방향 바꾸기·떼기는 바로 반영한다.

### 3.2 막는 때

| 상태 | 화면 |
| --- | --- |
| 로봇 상태를 받지 못함 | "로봇 상태를 받지 못해 쓸 수 없습니다." |
| 목적지 주행 중·경비 중·대화 중(`dialog_state` 가 비었음·idle·none·arrived·failed·estopped 가 아님) | "현재 주행 중입니다.\n주행이 완료된 후 사용해주세요." |
| 연결 끊김 | 버튼 흐리게, 누를 수 없음 |

- 수동으로 움직이는 중에 목적지·홈 복귀·경비가 시작되면(`goal_sent`·`accepted`·`return_home_sent`·경비 사건) 앱이 바로 수동 명령을 멈춘다.
- Nav2 는 끄지 않는다. Nav2 는 목적지가 있을 때만 `/cmd_vel_req` 를 내므로, 목적지가 있는 동안 막아 두면 두 명령이 섞이지 않는다.

### 3.3 장애물 보호를 어떻게 정했나

수동 명령은 `/cmd_vel_req` 로 바로 가서 Safety(`cmd_timeout_sec` 0.5)를 거쳐 모터로 간다. Nav2 의 collision_monitor 는 거치지 않는다.

- A안(Nav2 가 떠 있으면 `/cmd_vel` 로 보내 collision_monitor 를 거치기)은 하지 않았다.
  Nav2 가 없으면 못 움직이고(Nav2 가 연결되지 않은 상황에서도 굴러가는 것이 목적), 정지 영역(앞 0.21~0.48 m)에 점 2개만 있어도
  뒤로 빼기·돌기까지 0 으로 막으며, 라이다만 보므로 낮은 물체는 어차피 못 본다.
- B안(출발 가속 제한)만 넣었다. 0 → 0.7 계단 명령을 0.23 s 경사로 바꿨다.
- 그래서 수동 주행 중에는 라이다로 자동으로 서지 않는다. 이것은 실기 안내에도 적었다.

## 4. 지도 그리기 조종판 속도

- 지도 모드 ② 작성 중 조종판에 속도 칸(0.1~0.7 m/s, 기본 0.3)을 넣었다. 회전·가속은 수동 주행과 같다.
- 문구: "버튼을 누르고 있는 동안만 움직입니다.\n지도 작성 적정 속도는 0.3 m/s입니다."
- 0.3 이 적정인 근거: Cartographer 예측 탐색 창이 0.1 m 라 0.5 m/s 면 스캔 사이 이동이 10 cm 로 창 경계에 닿는다(`docs/cartographer_corridor_mapping.md` 4절).
- 홈 위치 조종판(지도 설정 → 홈 위치)은 예전 그대로 0.3 m/s·0.3 rad/s 고정, 가속 없음.

- Nav2 의 RangeSensorLayer 는 실행 중에 켜고 끄는 파라미터가 없다. 그래서 드라이버가 '없음'을 보내 그 부채꼴을 비우게(`clear_on_max_reading`) 한 뒤 발행을 멈춘다.
- 새 파라미터는 만들지 않았다(파이썬 판 드라이버와 파라미터 목록이 같아야 한다는 소스 계약).
- 뒤·뒷바퀴 옆 초음파는 도킹용 `/ultrasonic/dock_*` 라 costmap 에 들어가지 않고, 이 스위치와 무관하다.
- 앞 두 채널은 뒤와 같은 라운드를 나눠 써서 한 바퀴 315 ms 그대로, 앞은 약 3.2 Hz.

### 5.2 끌 때 생기는 일(사용자 확인 11-19 "그대로 둬")

- 0.38 m(라이다 높이)보다 낮은 물체는 앞 초음파만 본다. 끄면 그런 물체를 못 피할 수 있다.
- 끈 뒤 1.2 s 에 costmap 을 통째로 한 번 비운다. 라이다 장애물은 다음 스캔(약 0.1 s)에 다시 들어온다.
- 화면 문구: "초음파를 끄면 0.38 m보다 낮은 물체를 피하기 어렵습니다."

  확인 창(`showVicaDialog`, 15곳). 휴대폰 '움직임 줄이기'를 켜면 효과를 끈다.
- **폰 지도 고정**(`MapWorkLayout`): 폰 세로(폭 < 600 px, 키보드를 뺀 본문 ≥ 560 px)도 세로 태블릿처럼 지도를 위에 고정한다.
  지도만 고정하고 지도 고르기 줄·목적지/수동 버튼은 스크롤 칸 맨 위로 옮긴다. 지도 높이는 본문의 3분의 1(220~440 px).
  키보드가 열린 동안은 지도를 접고(0.2 s), 칸은 그대로 두어 입력하던 글과 초점이 남는다.
  적용 화면: 주행(목적지 주행)·지도 설정·물류 배송·현재 위치·경비(경로 편집 포함)·지도 작성 ②. 웹·태블릿·지도 없는 화면은 그대로.

## 7. 초음파 잔상 확인과 VCC 수리(11-14)

- **잔상**: 0.1 s 마다 재생 costmap(초음파 층)의 장애물 칸을 나눴다. 빔 안에서 '없음'으로 읽는데 남은 칸(빔 안 잔상)은 run102 실주행 3.0 %,
  run104 정지 시험 2.5 % 였다(그림 3). 1 s 넘게 남은 빔 안 잔상은 VCC 차선을 붙잡은 적이 없었다.
- **복귀 대기 이어서 셈**(`3875bf1`): 레일 쪽 후보끼리 1등이 바뀔 때마다 1 s(`return_clear_time`)를 처음부터 다시 세던 것 → 이어서 셈.
  단계 복귀 2.4~5.0 s → 1.4 s(run106).
- **새 경로마다 목표 차선도 같이 옮김**(`6695638`): `/plan` 이 약 1 s 마다 로봇 위치에서 다시 그려질 때 offset 만 다시 맞추고 target 은 그대로 둬서,
  새 경로마다 옆으로 0.2 m 씩 더 가려 했다. 새 경로 첫 주기에 시작된 어긋남이면 target 도 같은 만큼 옮긴다(`LaneSelector::shiftTarget`).
  레일에서 옆 거리 중앙 0.32 → 0.20 m, 0.6 m 넘게 벗어난 시간 29 → 7.6 %(그림 2).

## 10. 발견과 남은 일

- 지도 그리기 조종판 속도는 실기로 아직 안 봤다(사용자가 나중에).
- 수동 주행 중에는 라이다로 자동으로 서지 않는다(3.3). 운영에서 바꿀지는 그때 정한다.
- 도크 안(`dialog_state` docked)에서는 수동 주행이 막히고 "현재 주행 중입니다" 문구가 나온다. 도킹 중 원격 주행은 도킹 쪽 결정(버튼 숨김)을 따른다. 문구를 따로 둘지는 미정.
- 웹을 두 노트북에서 띄우면 끊기는 것(기본 주소 127.0.0.1·재연결 5번 뒤 포기·ping 없음)은 원인만 정리했고 고치지 않았다.
- VCC: 마지막 장애물 비틀거림 대책(회전 속도 상한 / 복귀 늦춤)은 결정 대기, VCC 브랜치(`feat/vica_customized_controller`) 정리 대기.
- 빔 밖 기억(앞 통로 장애물 칸·초의 17 %)은 라이다 층과 엮지 않기로 했다(11-16).
- APK 는 노트북에서 빌드한다(젯슨은 aapt2·gen_snapshot 이 x86 전용).
