# 2026-11-18 ~ 11-19 앱 '지도 수정' — 지우기·부분 스캔·되돌리기

이미 만든 주행 지도에서 **바뀐 곳만** 고치는 관리자 앱 기능이다. 사각형으로 고른 구역을 빈칸으로 만드는 **지우기**,
로봇이 선 자리에서 반경 1·2·3 m 를 라이다로 다시 재 바뀐 칸만 고치는 **부분 스캔**, 가장 최근 수정을 원래대로 돌리는
**되돌리기** 세 가지다. 고친 지도는 Nav2 를 재시작하지 않고 `map_server` 의 `load_map` 으로 바로 주행에 반영한다.
11-19 에 운영 브랜치 `after_feedback_waiting`(앱 `7a938be`·ROS `7c41522`)에 합쳐 평소 유닛으로 실기했다.

  그림 만드는 스크립트 `docs/map_fix/make_figures.py`·`capture_body.py`, 설계서·계획서 `docs/superpowers/`
- 원자료 전체: 젯슨 `~/vica_data/map_fix_tests/2026-11-19_dock/`(실기 로그·확인 도구·진행 기록 `ledger/`)

## 1. 왜 필요한가

지도는 SLAM 으로 한 번 그린다. 그 뒤 가구·칸막이·충전 도크처럼 **고정 장애물**이 바뀌면 지도와 실제가 어긋난다.

- **위치 추정이 흔들린다.** AMCL 은 라이다 끝점이 지도의 벽과 겹치는 정도로 위치를 맞춘다. 지도에 없는 물체가
  빔을 가리면 맞는 빔이 줄어 위치 맞춤 점수가 떨어진다(11-19 도크 앞: 61~72 %).
- **경로가 꼬인다.** costmap 의 static layer 가 지도를 그대로 쓰므로, 치운 물체는 '유령 장애물'로 남아 길을 막고,
  새 물체는 지도에 없어 가까이 붙는다.
- **처음부터 다시 그리면 비싸다.** 다시 매핑하면 좌표계가 달라져 장소·홈·도크·금지구역·레일을 모두 다시 맞춰야 한다.
  바뀐 곳만 고치면 좌표계와 나머지 저장물은 그대로다.

## 2. 구성

```
앱(Flutter 웹 5000)  ─rosbridge 9090─  map_fix_node(/vica/map_fix, MapFix.srv · /vica/map_fix/state 토픽)
                                           │ 지도 파일 maps/<지도>.pgm·png (+ .fix_backup/<지도>/ 백업 10개)
                                           │ load_map → map_server → /map → AMCL·costmap
                                           │ /map 의 map_load_time 으로 반영 확인
map_list_node ─ image_version(그림 수정 시각) → 앱이 새 그림을 받음
Mission Manager ─ 다음 주행 시작 때 새 지도를 읽음(그 전까지는 앱이 알림)
```

- `map_fix_node` 는 운영 앱 유닛(`vica-app`, `supervisor_bringup.launch.py`) 안에서 뜬다. 쉬는 동안 43 MB, 한 번 쓰면
  numpy 가 올라와 약 136 MB. 라이다·오도메트리·TF·`/amcl_pose` 구독은 요청이 왔을 때 열고 120 s 쉬면 닫는다.
- 요청은 서비스 하나 `MapFix.srv(map_id, action, args_json)` 로 받는다. action = `get`·`erase_count`·`erase`·`scan_check`·
  `scan_start`·`scan_cancel`·`scan_apply`·`scan_discard`·`undo`.

## 3. 기능과 조건

### 3.1 잠금 — 언제 거절하는가

| 사유 | 조건 | 막는 것 |
| --- | --- | --- |
| `busy_driving` | 목적지가 살아 있음 · 미션이 일하는 중 · 로봇이 움직임 | 전부(조회 제외) |
| `no_status` | `/robot_status` 를 못 받음(모르면 하지 않는다) | 전부(조회 제외) |
| `busy_session` | 부분 스캔이 진행 중 | 지우기·되돌리기·새 부분 스캔 |
| `not_current_map` | 고르는 지도가 지금 주행 지도가 아님 | 부분 스캔만(지우기는 파일만 고치고 다음 주행 때 적용) |

### 3.2 지우기

- 지도 위에 사각형을 그려 **한 번에 10곳까지**(한 변 최소 5 cm) 고른다. [구역 표시 | 지도 이동] 전환으로 지도를 움직이며 그린다.
- 사각형 안의 검은 칸(0)과 회색 칸(205)을 빈칸(254)으로 바꾼다. 먼저 `erase_count` 로 바뀔 칸 수를 보여 준 뒤 확인을 받는다.

### 3.3 부분 스캔

순서: **위치 맞춤 → 물러나기 5 s → (구분 안 됐으면 다시 맞춤) → 스캔 5 s → 변경 판정 → 미리보기(5분) → 적용 또는 버리기.**
반경은 1·2·3 m(기본 2 m), 지금 주행 지도에서만 된다.

1. **위치 맞춤** — 틀린 자세로 얹으면 그 오차가 지도에 남으므로 AMCL 자세는 출발값으로만 쓴다.
   - 거친 맞춤: `pose_score.search_pose`(AMCL 과 같은 잣대).
   - 벽 겉 칸 10 cm 안에 떨어진 빔만 남긴다(안 바뀐 벽). 몸체 + 사방 20 cm 안의 빔은 처음부터 버린다.
   - 정밀 맞춤: 남긴 빔의 '벽 겉 칸 가운데까지 거리' 제곱 평균이 가장 작은 자세(±5 cm·±1°).
   - 통과 조건: 남긴 빔 ≥ 60개·≥ 50 %, 거리 RMS ≤ **5 cm**, AMCL 에서 옮긴 양 ≤ 30 cm·10°.
   - 구분 검사: 자세를 앞뒤·좌우 ±10 cm, 방향 ±2° 밀어 RMS 가 2 cm(방향 1 cm)보다 적게 늘면 그 축은 '구분되지 않는다'.
2. **구분되지 않는 축** — 물러나기 5 s 뒤 사람이 비킨 스캔으로 한 번 더 맞춘다. 그래도 안 되면, AMCL 이 그 축을 **10 cm 안으로**
   확신할 때(`/amcl_pose` 공분산을 로봇 기준으로 돌린 표준편차)만 그 축에 지금 로봇 위치를 쓰고 미리보기에 안내한다.
   방향(yaw)은 쓰지 않고 거절한다(3.7° 틀리면 3 m 끝에서 19 cm).
3. **변경 판정**(반경 안, 스캔 N 장):
   - 새로 생김: 끝점이 그 칸에 떨어진 스캔이 0.8 N 이상, 주변 1칸 안에 지도 벽이 없음.
   - 없어짐: 빔이 그 칸을 지나간 스캔이 0.8 N 이상, 끝점이 떨어진 스캔은 0.1 N 이하. 끝점 앞 0.10 m 는 지나간 것으로 안 센다.
4. **멈춤 조건**: 미리보기 전에 로봇이 움직이면(0.02 m/s·0.05 rad/s) `moved`, 주행이 시작되면 `busy_driving`, 스캔이 2 s 끊기면 `no_pose`.
5. **미리보기**: 바뀐 칸을 지도 위에 **실제 크기 그대로** 그리고(새로 생김 짙은 청록, 없어짐 주황), 같은 스캔으로 잰
   위치 맞춤 % 를 수정 전·후로 보여 준다.

### 3.4 되돌리기

가장 최근 수정부터 하나씩 되돌린다. 백업은 지도마다 최근 10개. 그 사이 지도를 다시 맞춰 크기·해상도·원점이 다르면 되돌리지 않는다.

### 3.5 Nav2 반영

- 지금 주행 지도면 `load_map` 을 건다. Nav2 응답 **또는** `/map` 의 `map_load_time` 이 요청 뒤인 것 중 먼저 오는 것으로 확인한다(5 s).
- Nav2 가 지도를 못 읽으면 파일을 백업으로 되돌린다(`apply_failed`). 응답이 없으면 파일은 두고 잠금 밖에서 다시 건다(5 → 10 → … → 60 s).
  Nav2 가 꺼져 있으면 켜질 때 읽는다.
- Mission Manager 는 다음 주행을 켤 때 새 지도를 읽는다. 그 전까지 앱 알림: "Mission Manager에는 적용되지 않았습니다. / 주행을 껐다 켜면 적용됩니다."
- 파일은 임시 파일로 다 쓴 뒤 한꺼번에 바꾸고(원자적 교체·fsync), 권한(664)은 그대로 둔다.

### 3.6 기능 사이의 연결

- 지우기·부분 스캔·되돌리기는 **같은 백업과 같은 반영 경로**를 쓴다. 부분 스캔의 적용도 되돌리기로 돌릴 수 있다.
- 시작 전 '위치 맞춤 확인'(`scan_check`)은 부분 스캔 첫 단계와 **같은 판정**이다. 통과해야 [스캔 시작] 이 열린다.
- 초기 위치 잡기(`pose_bootstrap`)는 지도 내용 지문(`map_fingerprint`)으로 거리표를 다시 만든다 — 지도를 고치면 다음 초기 위치 잡기가 새 지도로 계산한다.
- 장소·홈·도크·금지구역·레일은 같은 좌표계라 그대로 맞는다. 지도를 고쳐도 다시 찍을 필요가 없다.
- 앱은 수정이 받아들여지면 지도 목록을 다시 받아 `image_version` 이 바뀐 새 그림을 띄운다.
